# 订单收款登记去重（F08）

订单收款接口现在要求客户端提供UUID `request_id`。同一次登记在超时、重试和并发请求中复用该值；服务端在当前租户、账号权限检查之后加事务锁，只写一条付款记录。旧客户端缺字段明确返回400。相同标识更改金额或参考号返回既有 `COMMON_IDEMPOTENCY_MISMATCH`（422），不会改账。该业务凭据保存在订单付款记录中，不依赖24小时HTTP响应缓存。

同一订单已有非空银行参考号时，相同金额返回已有登记，不重复加款；金额冲突拒绝。新请求标识会绑定到这条收款凭据，不能再换内容使用。不同标识、无参考号的等额分期仍可合法登记。没有替用户判定两个不同的银行参考号是否代表同一实际到账；历史重复收款需人工核对，不自动删账。

前端提交期间锁定按钮、金额和参考号，首次发送前把该意图存入按租户/用户/订单区分的会话存储。网络结果不明时保留原标识和数据；刷新后仍能重试原请求。成功后清空意图和金额，下一笔才生成新标识。已收齐并完成的订单仍可查询式重放已有收款，不能新增付款。这里是手工收款登记，没有接入或执行支付。
