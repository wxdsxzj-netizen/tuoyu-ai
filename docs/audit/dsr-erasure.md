# S5：数据主体删除范围与完成条件

本实现解决软件声明“删除完成”与普通副本残留之间的不一致；不替平台或租户确定法定保留依据。

## 自动处理清单

主体匹配使用当前租户的规范化邮箱、原始邮箱（大小写无关）、联系人 ID、报名 ID 和派生会话关联。包含软删联系人。首次执行保存不含地址的关联 ID，完成前再次执行以覆盖两次操作之间到达的副本。

| 存储 | 处理 |
|---|---|
| Contact | 擦除姓名、邮箱、电话、WhatsApp、职位/部门/资历、地域/语言、个人链接及字段血缘；保留外键空壳并标记删除/抑制 |
| Enrollment / MessageDraft | 停止报名，清理闸门及邮件线程快照；草稿正文、标题、事实、审核说明清空并阻止发送 |
| OutboundMessage / InboundMessage / DeliveryEvent | 擦除主体地址、标题、正文、邮件标识及个人载荷；保留状态统计 |
| Conversation / Message | 关闭会话，擦除地址、标题、正文、译文、邮件头和 detail，包括笔记 |
| Inquiry / Handoff | 擦除地址、需求、评分载荷、摘要、背调及建议回复；关闭/到期，取消 SLA |
| WidgetSession | 清空访客资料、聊天记录、同意载荷、IP 哈希，关闭并更换令牌哈希，旧访客令牌失效 |
| WhatsApp / LinkedIn / PhoneTask | 清除已关联联系人的号码、正文、个人链接、脚本、备注及提供商标识；撤回同意、停止排队任务 |
| AlibabaLead / ContactChange / DataCorrection | 清除匹配的入站源载荷和本租户个人字段快照；不修改共享实体 |
| Notification / Task | 清理上述对象派生的标题、正文/备注并取消未完成任务 |
| ConsentRecord / Suppression | 清除明文证据与备注；保留防止再次联系所需的不可逆地址哈希 |
| DataExport | 同租户已有导出全部失效，删除受管目录内的 ZIP；排队任务不可恢复失效文件，重新申请只导出当前数据 |
| IdempotencyKey | 当前租户响应正文全部清空；已完成记录改为 409 凭据，进行中记录仍为不确定状态，之后到达的旧响应也不再保存正文 |
| 当前 DsrRequest | 完成时清除请求人姓名/联系方式、明文地址、原始详情、更正载荷及自由文本备注；保留哈希、时间、状态与统计证据 |

## 必须阻止自动完成的情况

执行结果 `erasure.manual_review` 列出未处理存储及记录数。只返回分类和数量，不返回保留内容。非空时完成操作返回 409，工单继续处于 processing：

- 不可变审计中仍含主体地址；不能绕过数据库只追加规则。
- 来源为导入且仍有源归档，需要核查附件内容和保留范围。
- 已知共享联系人来源或平台邮箱验证缓存仍在，需要平台流程处理，租户删除不得直接改其他租户依赖的数据。
- 知识库、财务确认、背调/Agent/Job 快照、历史 DSR 等未分类存储中仍含精确主体地址。检查当前租户所有普通文本/JSON/数组列，不能擅自删除整条业务记录。
- 旧导出不在预期受管路径、是符号链接或无法清理；不删除异常目标，也不宣称完成。

这不是任意自由文本中的人名/别名识别器；不能凭姓名推断并批量删除无关联业务记录。外部已下载副本、第三方系统、邮件服务器和不可在线改写的备份需要各自的数据清单与保留/恢复流程。本实现不把这些外部步骤宣称为已执行。

## 一致性与迁移

DSR 操作锁定工单行；导出构建、清理及幂等领取按租户锁排序。真实 PostgreSQL 并发回归确认构建中的导出提交后会被清理，旧排队构建不会重新发布文件。正在传输或已下载的数据不能通过删除服务器文件追回。

迁移 `0016` 为幂等记录加入 tenant_id 和 discard_response。无法可靠归属的历史缓存正文清空并禁止迟到响应回填；不确定操作保持 status_code=0。降级删除新列但不恢复已擦除正文。切换版本需先排空旧写进程；旧进程不理解新字段，不能并行运行。

结果不确定时必须对账，不删除领取记录或换键重试。源归档、不可变证据、共享数据与外部副本的保留依据、平台办理入口属于仍需业务确认的工作，不提供绕过 409 的“强制完成”开关。

## 增补：失败或崩溃导出的磁盘残留

独立复核发现固定ZIP写入后、`file_path`登记前发生错误可能留下部分个人数据。已用真实文件失败注入复现：联系人JSON成功写入后令下一次写入失败，旧代码仍允许DSR完成却保留ZIP；不是已确认的生产事故。

导出现在以仅进程用户可读写的随机临时文件生成完整ZIP，成功关闭后原子发布。生成在数据库保存点内，SQL中止先回滚保存点再登记失败；错误只存异常类型，不保存可能含个人数据的参数。失败清理本导出的临时文件和最终文件。进程强制终止可能绕过清理，因此DSR同时扫描本租户严格UUID命名的受管文件，包括没有`file_path`、已过期记录以及数据库事务未提交留下的孤儿文件。

扫描只检查配置上传目录下的直接`exports`目录，不递归、不接受符号链接、不删除其他租户文件、不放宽已有路径校验；目录、文件类型、路径或删除失败会阻止完成。外部副本和未知命名历史文件仍需受控盘点，不能凭邮箱内容搜索后随意删除。

验证：修复前新增3项失败；修复后DSR/导出权限/原并发回归19通过（31.59s）。增补真实SQL除零中止后，与跨会话/聊天回归合跑19通过（26.30s），其中DSR11项。命令：

```sh

TL_SECRETS_FILE=/dev/null TL_DATABASE_URL="$AUDIT_DATABASE_URL" TL_REDIS_URL="$AUDIT_REDIS_URL" .venv/bin/python -m pytest -q -p no:cacheprovider backend/tests/test_audit_dsr_erasure.py backend/tests/test_audit_inquiry_links.py backend/tests/test_audit_widget_response.py
```

无数据库迁移；回退会恢复部分ZIP残留风险。此修正不解除本文件列明的保留、共享来源及外部副本业务核查要求。

## 已确认的办理范围

用户已确认：普通业务副本按删除流程清理；审计记录、财务证据和涉及其他租户的共享数据保留人工核查关卡。核查未完成时不得显示“删除完成”。没有给定保留依据、期限或责任人的类别继续处于人工办理状态，不自动到期销毁，不跨租户删除共享来源。此范围选择已确认，工单本身仍需按实际证据逐件办理。

增补兼容：旧版记录的相对文件路径在解析后必须精确等于受管目标，且路径本身不能是符号链接；通过后按规范化受管路径清理。并未放宽任意路径删除权限。
