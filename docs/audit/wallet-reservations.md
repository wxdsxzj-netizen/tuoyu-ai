# 钱包与预算预占修复

覆盖 AI-BILL-02、AI-BILL-03、AI-BILL-12。所有钱包写入先取得租户行锁；并发会话从数据库重新读取余额、订阅和发票状态。付款发放使用租户内唯一 `invoice:<id>` 业务键，重复付款确认不能再次赠点。发票编号改用随机标识避免跨租户计数竞争。

`credit_reservations` 保存每个任务的原始预占、真实剩余额、成员、部门和创建预算月份。消费减少剩余预占，释放只允许退还尚未消费部分；预占完成后不会继续显示为冻结余额。硬预算用“本月已消费 + 全部尚未结清预占”检查，跨月未结预占也不能绕过当月预算。部门归属在预占时保存，调部门不会搬移历史费用。

## 迁移0018

在停用旧钱包写入进程后执行迁移。迁移先检查历史预占是否超额消费/释放或缺失任务标识；发现异常就失败，原账本不改写。应通过已验证的业务凭据核对历史差额，不可删除账本或任意增加余额来通过检查。

剩余额按历史 hold、held consume、release 回填；已有付款入账关系补唯一业务键。历史部门只能按现有成员部门回填，无法还原过去的组织调整，历史部门报表须标记此限制。

降级0018不会删除原始账本，但会移除剩余预占表、业务键和部门快照。必须停止所有钱包写入，导出这些元数据后才考虑降级；旧版本重新开放会恢复并发与预算缺陷。再次升级可从账本重建金额，不能完整恢复历史部门和业务键。禁止在生产直接试迁移或回退。
