# 供应商入口统一计量

AI-BILL-01：普通联系人补全、瀑布、单个/批量邮箱验证和Agent复用统一钱包/预算检查；背调也在抓取前检查费用上限。只有通过授权检查后才能调用供应商，钱包锁保持到结果落库与结算完成。使用调用者、作业创建者或序列负责人归属费用，成员与部门预算不能通过异步入口绕开。

补全按新增有效邮箱结算，重复邮箱和新鲜结果不重复扣点；同租户并发请求在锁后检查缓存。供应商超出请求上限的结果不超量计费，无效邮箱不计为成功发现。验证的本地语法/MX/退信判断、缓存和未知/失败结果免费；Agent预占只结算一次。批量验证逐条提交结果和费用，后续条目达到预算时已完成条目保留，作业明确失败。

先取得6项失败断言，之后验证普通入口余额/预算、供应商调用次数、Agent预占、同租户两会话并发、无效结果、缓存及批量中断。旧功能测试中需要真实执行付费验证/补全的案例补充明确合成余额，没有放松生产检查。全部供应商调用为替身，未使用真实供应商Key。

验证记录：原功能扩展46通过（94.85s）；补全/验证并发及钱包21通过（23.16s）；发送/P4扩展首次35通过、1个旧测试缺验证余额失败，补足余额后相关发送/闸门/计量18通过（34.36s）；最后增加背调前置检查后的计量/P5共18通过（63.20s）。最终计量专项12项，Ruff通过。

这些检查保证内部余额与预算边界；外部供应商不属于数据库事务，不能据此声称供应商侧收费恰好一次。供应商超时和数据库提交失败仍应按调用凭据核查，不能盲目重试。钱包锁期间同租户付费动作会串行，这是当前实现的吞吐限制。
