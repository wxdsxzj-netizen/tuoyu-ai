# 发送可靠性修复：O-01 / O-04 / O-13

基于首批和入站/最终合规修复继续修改。适用于序列邮件和人工收件箱回复。应用版本仍为 0.1.0，本记录不是发布声明。

## 行为

- SMTP 前提交 `SendIntent` 与状态为 `sending` 的 OutboundMessage，随后重新锁定、读取并检查发送条件。序列业务键是租户内 enrollment + step；修改草稿版本不能绕过已经发送或未知结果的记录。人工回复按会话、最新入站消息、正文、主题、收件人和发件箱生成稳定业务摘要，同一请求重试会读取已完成结果。
- 每条发送独立提交。后续条目失败只回滚该条；前一条已成功发送的记录不受影响。PostgreSQL 唯一键与租户行锁保护领取及配额计算；同一租户的 SMTP 最终发送阶段串行，其他租户可独立执行。这是优先保证可靠性的保守实现，需要在压测后评估吞吐。
- SMTP DATA 阶段断开连接视为 `unknown`。SMTP 后进程退出或数据库事务中止时，已经提交的 `sending` 记录仍存在。两者都不会因 TTL 或任务重新投递而自动重发，也不把未知结果提示成“未发送”。
- 发送意图保留 Message-ID。明确临时拒绝才能自动重试；10/20/40 分钟退避后排除失败邮箱，尝试其他可用邮箱；全部耗尽进入核查队列。审批草稿和收件人条件仍在每次尝试前重新检查。
- catch-all 冷邮件按租户 UTC 自然日限制：收件域名当天至多一封，邮箱已发送及未决冷邮件中的 catch-all 占比不得超过 10%。预留记录也占额度；无有效发送量时不会先发 catch-all。角色邮箱没有凭空增加未定义的独立额度，界面提示改为实际实现的风险说明。
- DSR 擦除处理新增发送记录：邮件副本擦除，相关意图标记 `erased`，不能重新派发或人工恢复。发送器和擦除流程共享租户锁，发送前重新读当前擦除/暂停状态。

## 人工核查

投递页面新增“待核查发送”，使用服务端分页。需要 `sequence.approve` 权限；跨租户对象不可读取或修改。发送中的新记录等待两分钟后才允许核查。操作者必须检查邮件服务器/提供商日志，填写可追溯依据，再选择：

- 明确已接收：只补齐消息、统计和序列步骤，不执行 SMTP，不重复记账。
- 明确未接收：释放未知结果占用，允许后续正常闸门重试；已有人工/合规停止状态仍保留。重试耗尽需修复原因后明确恢复。

无法判断时保留待核查，不得把缺少日志当作未接收。核查 API 写审计记录；重复核查已完成记录返回冲突。此流程依赖人工验证外部日志，不声称 SMTP 提供 exactly-once。

API：`GET /api/v1/delivery/intents`；`POST /api/v1/delivery/intents/{id}:reconcile`，正文包含 outcome（sent/not_sent）及 evidence（10–2000 字）。

## 迁移与兼容

新增 `0017_send_intents`，无破坏性重写历史邮件。已有成功草稿会占用业务发送位置；历史重复邮件无法由本修复撤回。

必须先运行迁移再启用新发送器。旧代码不识别未决意图，不能在仍有未决发送时直接回退并开启外发。回退前停止全部发送任务和人工回复，核查并归档凭据；迁移降级在 send_intents 非空时主动拒绝删除。不得为通过降级而清空证据。测试仅在隔离数据库完成，未部署。

## 验证

原批次回滚、成功后落库失败、未知结果自动重试失败断言已复现；人工回复的同类失败另行复现。catch-all 配额失败断言也已复现。

测试包含真实 PostgreSQL 双会话领取/配额竞争、SMTP 接收后子进程立即退出、实际 PostgreSQL 事务中止、逐条提交、临时重试换箱、DSR 删除、核查权限/租户边界；SMTP 为本地接收器或合成替身，不连接真实收件人。详细结果与命令登记于审计修复清单。
